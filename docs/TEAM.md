# Команда и зоны ответственности

Зоны ответственности определяет тимлид. Документ фиксирует, кто за что отвечает и по каким контрактам компоненты стыкуются, чтобы каждый работал в своей зоне, не блокируя остальных.

## Роли

### Тимлид, Go-бэкенд (kudesn1k1)

Архитектура и самая сложная часть системы.

- **Data plane целиком:** gateway, executor, песочница и абстракция рантайма, пул инстансов, кеш модулей, квоты, circuit breaker, кольцо и discovery (`dataplane/`).
- **Владелец контрактов data plane:** `api/invoke.openapi.yaml`, `api/dataplane-internal.openapi.yaml`, ABI скрипта.
- **Архитектурные решения и ADR** (`docs/adr/`), основной спек.
- **Go SDK** (MVP), нагрузочные тесты, Helm-чарт и развёртывание.
- **Распределение задач и ревью PR,** затрагивающих контракты.

### Backend, Python

Всё, что решает, «что разрешено», и всё, что видят люди через консоли.

- **Control plane** (`control-plane/`): API-ключи, тенанты, хуки, модули и их жизненный цикл, привязки, квоты, модель данных и миграции, хранилище модулей (MinIO).
- **Эндпоинт снимка конфигурации** по контракту `api/dataplane-internal.openapi.yaml`: control plane его реализует, data plane потребляет.
- **Оркестрация валидации модулей:** вызов эндпоинта валидации executor-а, хранение отчёта.
- **Владелец контракта консолей** `api/control-plane.openapi.yaml`, генерируется из FastAPI.
- **Хранилище вызовов и SSE-стримы** для консолей (MVP).
- **Python SDK** (`sdk/python/`) по контракту `api/invoke.openapi.yaml`.
- **Бэкенд демо-магазина** (`demo-shop/`): оператор для платформы, API для витрины.

### Frontend

- **Консоль оператора и консоль тенанта** (`web/`, route groups `(operator)` и `(tenant)`).
- **Витрина демо-магазина** (route group `(storefront)`).
- **Моки API** (MSW) по контрактам из `api/` для работы до готовности бэкенда.
- **E2E-тесты** на Playwright.
- **Потребитель** `api/control-plane.openapi.yaml` и API магазина. В data plane не ходит никогда.

## Контракты

| Контракт | Файл | Владелец | Реализует | Потребляет |
|---|---|---|---|---|
| Публичный Invoke | `api/invoke.openapi.yaml` | тимлид | data plane | Python SDK, демо-магазин, любой оператор |
| Снимок конфигурации | `api/dataplane-internal.openapi.yaml` | тимлид | control plane | data plane |
| Валидация модуля | `api/dataplane-internal.openapi.yaml` | тимлид | data plane | control plane |
| ABI скрипта | основной спек, раздел про ABI | тимлид | data plane | авторы скриптов |
| API консолей | `api/control-plane.openapi.yaml` | backend, Python | control plane | фронтенд |
| API магазина | `api/demo-shop.openapi.yaml` | backend, Python | демо-магазин | витрина |

### Правила изменения контрактов

- Контракт меняет его владелец через PR. Потребители в ревьюерах.
- Внутри версии (`/v1`) изменения только добавляющие: новые необязательные поля, новые эндпоинты, новые значения перечислений там, где это оговорено. Удаление, переименование и смена типа означают новую версию.
- Клиенты игнорируют неизвестные поля (tolerant reader). Благодаря этому добавление поля ничего не ломает.
- Реализация не опережает контракт: сначала PR в `api/`, потом код.
