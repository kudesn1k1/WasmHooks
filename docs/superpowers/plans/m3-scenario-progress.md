# M3 · стенд и приёмочный сценарий

Команда полного прогона и параметры описаны в [инструкции kind](../../../deploy/kind/README.md). Стенд использует выделенный контекст, PVC PostgreSQL и MinIO, отдельные процессы и готовность executor-ов, headless Service, секрет установки для T7. Настройка привязок проходит через публичный API. Сценарий проверяет владельцев по диагностике gateway и фактическим записям Invoke, сумму каждой покупки и предзагрузку уникального модуля до первого запроса у нового владельца.

Локально прошли восемь unit-тестов подготовки стенда, денежных сумм, записей executor-а, движения пар, fallback, выбора kind-узлов и структуры Wasm-секции. Серверный dry-run проверил все четырнадцать Kubernetes-ресурсов. После исправления пустой custom section повторная настройка двух существующих магазинов и трёх дополнительных пар прошла дважды в живом kind без пересоздания кластера. Executor провалидировал уникальный модуль предзагрузки и вернул ожидаемую скидку при Invoke. Измерения полного сценария записывает `run.py --output <path>`.
