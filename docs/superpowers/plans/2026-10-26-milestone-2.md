# Milestone 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Квоты тенанта на gateway и слоты CPU в executor-е, чтобы шумный тенант (поток вызовов или зависшие скрипты) упирался в свои лимиты, а остальные тенанты не замечали его; изменение квоты применяется без перезапуска. Доказать замером S7b на Linux, тестами, шагами e2e и генератором нагрузки.

**Architecture:** Gateway после разрешения привязки проверяет token bucket и счётчик одновременных вызовов тенанта (`internal/gateway/quota`), лимиты берутся из текущего снимка на каждом вызове. Executor перед арендой инстанса берёт слот CPU (`internal/slots`): ёмкость `max(1, GOMAXPROCS−1)`, доля тенанта на слотах и в очереди, выдача освободившегося слота наименее занятому тенанту. Генератор нагрузки и новые шаги e2e — в модуле `e2e/` на stdlib.

**Tech Stack:** Go 1.26, `golang.org/x/time/rate` (новая зависимость data plane), stdlib в `e2e/`; Docker Compose; GitHub Actions (`ci`, `bench`).

**Spec:** `docs/superpowers/specs/2026-10-26-milestone-2-design.md` (далее «спек M2»).

## Review Focus

1. **Гонка отмены и выдачи слота:** ждущий вызов отменён в тот момент, когда ему отдают слот. Слот не теряется и не выдаётся дважды; `Stats()` после теста — ноль занятых. Тест — Task 2.
2. **Квота отпускается на всех путях** gateway: ok, ошибка executor-а, паника не нужна, отмена вызывающего во время ожидания. Тест — Task 3/4.
3. **Снижение лимита на лету:** `concurrency_limit` 8 → 2 при 8 вызовах в полёте — новые вызовы ждут, пока в полёте не станет < 2; ничего не уходит в минус. Тест — Task 3.
4. **Справедливость:** merchant-b держит долю слотов и заполнил свою долю очереди — вызов merchant-a получает слот сразу или первым при освобождении, никогда не `overloaded`. Тест — Task 2 и Task 5.
5. **Промах таймаута под насыщением:** запущенные вызовы `infinite-loop` завершаются по таймауту без опоздания на десятки мс. Замер — Task 7.

### Task 2: Пакет `slots`

**Files:** `dataplane/internal/slots/slots.go`, `slots_test.go`; правило `"slots": {only: []string{}}` в archtest.

API (спек M2 §7):

```go
type Options struct {
	Capacity    int // running calls; <=0: max(1, GOMAXPROCS-1)
	TenantShare int // running calls of one tenant; <=0: max(1, Capacity/2)
	Queue       int // waiting calls; <=0: 4*Capacity; one tenant's share max(1, Queue/2)
}
var ErrOverloaded = errors.New("slots: overloaded")
func New(opts Options) *Limiter
func (l *Limiter) Acquire(ctx context.Context, tenant string) (release func(), err error)
func (l *Limiter) Stats() Stats // Running, Waiting int
func (l *Limiter) Capacity() int
func (l *Limiter) Queue() int
```

- [ ] Тесты первыми (TDD): сразу при свободном слоте; доля `max(1, cap/2)` — второй тенант получает слот, когда первый на доле; очередь `Queue` и доля очереди `max(1, Queue/2)` → `ErrOverloaded`; освобождение отдаёт наименее занятому тенанту, при равенстве старшему; отмена ожидания возвращает `ctx.Err()` и не оставляет записи в очереди; гонка «отмена в момент выдачи» (повтор в цикле, `-race`) — слот возвращается, `Stats()` в конце нулевой; `release` идемпотентна.
- [ ] Реализация: `sync.Mutex`, счётчики занятых слотов по тенанту, список ждущих (срез структур с каналом `granted` и номером поступления). Выдача — под мьютексом выбрать ждущего, отметить слот занятым за ним, закрыть канал. Ждущий в `select` на `ctx.Done()`: под мьютексом проверить, выдан ли слот; если выдан — вернуть его через обычное освобождение и вернуть `ctx.Err()`.
- [ ] Записи тенантов с нулём занятых и ждущих удаляются из map.
- [ ] Коммит `feat(dataplane): add fair CPU slots for running calls`.

### Task 3: Пакет `gateway/quota`

**Files:** `dataplane/internal/gateway/quota/quota.go`, `quota_test.go`; `go.mod`/`go.sum` (`golang.org/x/time/rate`); правило `"gateway/quota": {only: []string{}}` в archtest.

API (спек M2 §6):

```go
type Limits struct{ RateRPS, Concurrency int } // Concurrency >= 1; RateRPS 0: unlimited
var (
	ErrRateLimited  = errors.New("quota: rate limit")
	ErrConcurrency  = errors.New("quota: concurrency limit") // queue full or wait expired
)
func New(now func() time.Time) *Manager
func (m *Manager) Admit(ctx context.Context, tenant string, lim Limits) (release func(), err error)
```

- [ ] Тесты первыми: bucket ёмкостью `max(1, rate)` — `rate+1`-й вызов подряд `ErrRateLimited`; пополнение со временем (инжектируемые часы через `rate.Limiter.AllowN(now, 1)`); `RateRPS 0` — без ограничений; параллельность — `Concurrency` вызовов проходят, следующий ждёт и проходит после `release`; очередь длиной `Concurrency` — сверх неё сразу `ErrConcurrency`; истёк дедлайн в ожидании — `ErrConcurrency`; отмена вызывающего — `context.Canceled` (обёрнутая); изменение лимитов на лету в обе стороны (Review Focus 3); состояние тенанта удаляется только когда нет вызовов, нет ждущих и bucket полон (`TokensAt(now) >= burst`) — последовательные вызовы сверх частоты по-прежнему отклоняются, а после простоя map пуста.
- [ ] Реализация: map тенант → состояние под одним мьютексом (мьютекс короткий); `rate.Limiter` на тенанта только при `RateRPS > 0`: при переходе 0 → N создаётся новый (полный bucket), N → M — `SetLimitAt`/`SetBurstAt`, N → 0 — limiter удаляется; `rate.Inf` не используется. Переходы 0 → 5 → 0 — отдельный тест. FIFO ждущих с каналами; рост лимита будит ждущих.
- [ ] Коммит `feat(dataplane): add per-tenant rate and concurrency quotas`.
