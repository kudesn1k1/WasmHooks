# Milestone 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Каркас монорепо, экспериментальные данные о рантайме и работающее ядро data plane (gateway + executor в одном процессе), которое исполняет wasm-скрипты тенантов с лимитами и изоляцией.

**Architecture:** Go-модуль `dataplane/`. Рантайм скрыт за интерфейсом `sandbox`, Extism — одна реализация. Gateway и executor общаются только через пакет `execproto`, связываются в `cmd/dataplane`; граница проверяется архитектурным тестом. Конфигурация — полный снимок из файла того же формата, что и будущий long-poll контракт.

**Tech Stack:** Go 1.26, Extism go-sdk v1.7.1 (wazero v1.9.0, проверка v1.12.0), santhosh-tekuri/jsonschema/v6 v6.0.3, golang.org/x/sync (singleflight), Rust stable + extism-pdk 1.4.x (фикстуры), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-24-milestone-0-design.md` (M0), `docs/superpowers/specs/2026-09-04-wasm-extension-platform-design.md` (основной). Исполнитель читает оба; при расхождении прав спек M0.

## Global Constraints

- Go-модуль: `github.com/kudesn1k1/WasmHooks/dataplane`, директива `go 1.26`.
- Коммиты от имени, настроенного в репозитории (kudesn1k1). Никаких упоминаний ИИ, никаких `Co-Authored-By`. Сообщения краткие и описательные, префиксы `feat:`, `fix:`, `test:`, `docs:`, `chore:`, `ci:`, `bench:`.
- Не использовать `-c user.name` и не менять git config.
- Только LF (`.gitattributes` уже есть). `.wasm` — бинарные.
- Никакого cgo. Всё должно собираться и тестироваться на `windows/amd64` и `linux/amd64`.
- Никаких внешних сервисов в тестах: без сети, без Docker.
- Список «Не входит в M0» из раздела 2 спека M0 обязателен для всех задач: квоты, circuit breaker, кольцо, ретраи между executor-ами, gRPC, Python, Postgres, MinIO, консоли, SDK, playground, прогрев инстансов, LRU модулей, второй язык, Compose, Kubernetes, k6.
- Экспорт скрипта всегда `handle`. ABI не зависит от языка, Rust только язык фикстур.
- Логи в коде через `log/slog`. Ошибки оборачиваются `%w`, проверяются `errors.Is/As`.
- Тесты пакета `internal/...` запускаются из `dataplane/`: `go test ./...`.

## Review Focus

1. **Конфиг тенанта утекает между инстансами одного модуля.** Extism отдаёт каждому инстансу ссылку на общий map `manifest.Config`. Ожидание: два тенанта с одним модулем `echo-config` видят каждый свой конфиг, в том числе при параллельных вызовах. Тест в Task 4 (`sandboxtest`), Task 8 (executor).
2. **Холодная компиляция съедает дедлайн запроса.** Первый вызов после старта компилирует модуль. Ожидание: компиляция не отменяется дедлайном запроса (идёт в отвязанном контексте, результат кешируется), а все привязанные модули компилируются при загрузке снимка до `readyz`. Тест в Task 8 (`TestExecutorCompileSurvivesShortDeadline`), Task 9 (`readyz` после preload).
3. **Инстанс после таймаута возвращается в пул.** Ожидание: после `timeout` и любого `handler_error` из `Call` инстанс закрывается, следующий вызов получает новый. Тест в Task 6 (`TestUnhealthyIsClosed`) и Task 8 (`TestExecutorTimeout` проверяет `Stats().Instances == 0` после таймаута).
4. **Параллельные вызовы одного тенанта сверх лимита пула.** Ожидание: лишние получают `unavailable` через `acquire_timeout`, а не висят до дедлайна и не создают инстансы сверх лимита. Тест в Task 6 и Task 8.
5. **Тело запроса с `payload` не-объектом, пустое тело, неизвестные поля, гигантский `deadline_ms`, отрицательный `deadline_ms`.** Ожидание: 400 для некорректных, `deadline_ms` зажимается в `[1, 30000]`, неизвестные поля игнорируются. Тест в Task 9 (`httpapi`).

```rust
use extism_pdk::*;
use serde::{Deserialize, Serialize};

#[derive(Deserialize)]
struct Customer { lifetime_spend: f64 }

#[derive(Deserialize)]
struct Input { #[allow(dead_code)] cart_total: f64, customer: Customer }

#[derive(Serialize)]
struct Discount { discount_percent: u32, reason: &'static str }

#[derive(Serialize)]
struct Output { result: Discount, effects: Vec<serde_json::Value> }

fn cfg_f64(key: &str, default: f64) -> Result<f64, Error> {
    Ok(match config::get(key)? {
        Some(v) => v.parse::<f64>().map_err(|e| Error::msg(format!("config {key}: {e}")))?,
        None => default,
    })
}

#[plugin_fn]
pub fn handle(Json(input): Json<Input>) -> FnResult<Json<Output>> {
    let threshold = cfg_f64("threshold", 1000.0)?;
    let percent = cfg_f64("percent", 10.0)? as u32;
    let result = if input.customer.lifetime_spend >= threshold {
        Discount { discount_percent: percent, reason: "loyal_customer" }
    } else {
        Discount { discount_percent: 0, reason: "none" }
    };
    info!("discount computed: {}", result.discount_percent);
    Ok(Json(Output { result, effects: vec![] }))
}
```

package sandbox

type Runtime interface {
	Compile(ctx context.Context, wasm []byte, spec ModuleSpec) (Module, error)
	Close(ctx context.Context) error
}
type ModuleSpec struct {
	MemoryMaxPages       uint32
	Timeout              time.Duration
	AllowedHostFunctions []string
}
type Module interface {
	Instantiate(ctx context.Context, cfg map[string]string) (Instance, error)
	Close(ctx context.Context) error
}
type Instance interface {
	Call(ctx context.Context, export string, input []byte) (CallResult, error)
	Close(ctx context.Context) error
}
type CallResult struct {
	Output []byte
	Logs   []LogLine

```go
type Manager struct {
	opts    Options
	mu      sync.Mutex
	pools   map[Key]*keyPool
	total   int                 // живые инстансы (idle + выданные + создаваемые)
	changed chan struct{}       // закрывается и пересоздаётся при каждом освобождении слота/инстанса
	closed  bool
	stop    chan struct{}
}
type keyPool struct {
	idle   []*entry // LIFO: последний отпущенный — самый тёплый
	active int      // выданные + создаваемые
}
type entry struct {
	inst     sandbox.Instance
	uses     int
	lastUsed time.Time
}
```

Алгоритм `Acquire`:
1. Под `mu`: если есть idle у ключа — снять последний, `active++`, вернуть lease (`cold=false`).
2. Иначе если `active+len(idle) < limit` для ключа:
   - если `total < GlobalMax` — зарезервировать слот (`total++`, `active++`), отпустить `mu`, вызвать фабрику **вне блокировки**; при ошибке под `mu` вернуть слот (`total--`, `active--`, `notify()`), вернуть ошибку фабрики;
   - иначе если есть idle-инстанс любого другого ключа — выбрать самый давно простаивающий, изъять, `total--`, закрыть его вне блокировки, и повторить шаг 2 (слот освободился);
3. Иначе запомнить `ch := m.changed`, отпустить `mu`, ждать `select { ch, ctx.Done(), timer(AcquireTimeout) }`; на `ch` — повторить с шага 1 (таймер общий на весь Acquire, не перезапускается); на таймер или ctx — `ErrSaturated`.

`Release(healthy)`: под `mu` (и с `sync.Once` на lease): `active--`; `uses++`; если `!healthy || uses >= MaxUses || m.closed` — `total--`, закрыть вне блокировки; иначе `lastUsed = now`, push в idle. `notify()`: `close(m.changed); m.changed = make(chan struct{})`.

`ReapIdle(now)`: закрыть idle с `now - lastUsed > IdleTTL`, удалить пулы без idle и без active, вернуть число закрытых. Фоновая горутина, если `ReapInterval > 0`.
