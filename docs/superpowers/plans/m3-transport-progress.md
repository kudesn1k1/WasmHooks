# M3. Внутренний транспорт

Кольцо строится по идентификаторам готовых executor-ов из gRPC Health. DNS headless Service даёт адреса для проверки. Виртуальные узлы позволяют сравнить назначение до и после удаления pod-а. Одно логическое выполнение отправляется максимум двум разным исполнителям с одним исходным дедлайном.

Реализованы `api/executor.proto`, проверки внутреннего bearer-токена, DNS discovery с проверкой готовности, 128 виртуальных узлов на executor и повтор по исходному дедлайну. `Stats` учитывает попытки по исполнителям, повторные отправки и успешные повторы. Временная ошибка DNS запускает повторную проверку известных адресов. Ответ DNS об отсутствии записей выводит адреса из кольца, а уже начавшиеся запросы получают возможность закончиться.

Проверено 23 ноября. Команда `go test -race ./internal/cluster -count=10` прошла за 6,878 с. Тесты используют TCP и подтверждают повтор на другом исполнителе после потери ответа, неизменность запроса, прекращение попыток с коротким бюджетом, отмену у исполнителя, проверку bearer-токена, изменение владельцев при смене готовности и сохранение ответа при удалении адреса во время исполнения. Полная команда `go test ./...` из `dataplane` также прошла.

По замечаниям ревью счётчики по ID сохраняются для действующих исполнителей и последних 16 выбывших с попытками. Более старые значения попадают в `RetiredAttempts`, при этом общее число попыток сохраняется. Тест проверяет 19 поколений pod-ов и возвращение ранее выбывшего исполнителя. Для ответа `unavailable` с положительным временем исполнения транспорт завершает вызов с неизвестным результатом без повтора. Оба дефекта воспроизведены до изменений. После исправлений прошли `go test -race ./internal/cluster -count=4` и `go test ./...`.
