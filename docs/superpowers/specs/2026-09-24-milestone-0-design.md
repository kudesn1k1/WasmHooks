# Milestone 0: каркас, спайк и ядро data plane

Design-спецификация вехи. Дата: 2026-09-24. Контрольная точка: пара ~2026-10-05.

Основной спек: `2026-09-04-wasm-extension-platform-design.md`. Этот документ его детализирует для M0 и фиксирует решения, принятые 24.09. Где документы расходятся, прав этот; основной спек обновляется по разделу 3.

---

## 1. Цель

Заложить архитектуру data plane в коде и получить экспериментальные данные о рантайме. Показать на паре работающее ядро: скрипт тенанта исполняется в песочнице с лимитами, сломанный скрипт одного тенанта не мешает другим.

## 2. Definition of Done

Каждый пункт проверяется человеком за несколько минут.

1. **Демо одной командой.** `go run ./cmd/demo` из `dataplane/` собирает и запускает data plane с конфигом из файла, прогоняет сценарий по HTTP и печатает таблицу:
   - тенант `merchant-a`, скрипт скидки: `ok`, скидка посчитана, выход прошёл схему;
   - тенант `merchant-b`, скрипт с бесконечным циклом: `timeout` не позже лимита хука плюс допуск;
   - `merchant-a` параллельно с зависшим `merchant-b`: по-прежнему `ok`, латентность в пределах нормы;
   - тенант `merchant-c`, скрипт-пожиратель памяти: `handler_error`;
   - тенант `merchant-z` без скрипта: `no_handler`;
   - payload, не проходящий схему входа: HTTP 400.
   
   В `dataplane/README.md` есть те же шаги в виде curl.
2. **`docs/spike-results.md`.** Таблица с результатами бенчмарков из раздела 12, характеристиками машины и выводами. Числа перенесены в основной спек (§8 SLO, §16).
3. **`go test ./...` зелёный в GitHub Actions на Linux**, включая тест изоляции тенантов с одинаковым модулем и архитектурный тест границ пакетов (раздел 5.3).
4. **Контракты в `api/`:** `invoke.openapi.yaml` (публичный), `dataplane-internal.openapi.yaml` (снимок конфигурации и валидация модуля). Командам понятно, как строить против них.
5. **ADR 0001–0004** в `docs/adr`.
6. **`docs/TEAM.md`** с зонами ответственности и владельцами контрактов.
7. **Один бриф.** `project-brief-1.md` слит в `project-brief.md`, расхождения сведены.
8. **Основной спек обновлён** решениями из раздела 3.

Stretch, если останется время, в порядке приоритета: эндпоинт `Validate` (раздел 6.3), `/metrics` в формате Prometheus, golangci-lint в CI.

### Не входит в M0

Не реализуется даже частично, даже если «почти ничего не стоит»: квоты тенанта и admission control, circuit breaker, кольцо, discovery и ретраи между executor-ами, gRPC, control plane и любой код на Python, Postgres, MinIO и S3, консоли и витрина, SDK на любом языке, playground и флаг `test`, прогрев инстансов, LRU-вытеснение скомпилированных модулей, второй язык скриптов, Docker Compose, Kubernetes, Helm, нагрузочные тесты k6. Контракты для части этого (снимок, валидация) фиксируются, реализация нет.

## 3. Решения от 2026-09-24 (дельта к основному спеку)

| # | Решение | Обоснование |
|---|---|---|
| D1 | Одна установка обслуживает одного оператора. Таблица `operators` убирается, API-ключи принадлежат установке (несколько, с именем, отзывные). | Self-hosted по определению. Мультиоператорность нужна только хостинговой платформе. |
| D2 | Тенант идентифицируется `external_id`, заданным оператором. В `Invoke` передаётся он. Уникален в пределах установки. | Оператору не нужна таблица соответствия идентификаторов. |
| D3 | Незарегистрированный тенант, как и тенант без активного скрипта, даёт `no_handler`. | Оператор вызывает хук для всех мерчантов и не обязан знать, кто что загрузил. |
| D4 | HTTP-статусы: 200 для `ok`, `no_handler`, `timeout`, `handler_error`; 429 для `quota_exceeded`; 503 для `unavailable`; 400/401/404/413 для ошибок запроса. Заголовок `X-Hook-Outcome` в каждом ответе с исходом. | Раздел 6.1.3. |
| D5 | Вход проверяется по схеме хука на gateway, ошибка это HTTP 400. | Понятная ошибка оператору вместо `handler_error`, скрипты защищены от мусора. |
| D6 | Публичный API на HTTP/JSON (OpenAPI). gRPC только между gateway и executor-ом после их разделения в MVP. В M0 граница между ними это Go-интерфейс. | Нет зависимости от protoc, удобно Python-клиенту, работает с curl. |
| D7 | Рантайм скрыт за интерфейсом `sandbox`. Extism одна из реализаций. | Go SDK Extism не обновлялся с мая 2025, привязан к wazero 1.9. |
| D8 | Конфиг тенанта передаётся через `config_get` из ядра Extism, а не через свою host-функцию. Ключ пула включает версию конфига. | Ноль кода в PDK. Изменение конфига естественно порождает новый пул, старый вымирает по простою. |
| D9 | Логи скрипта идут через функции логирования ядра Extism (`log_*`), лимит объёма на вызов в нашей обёртке. Своей host-функции `log` нет. | Уже есть в PDK всех языков. |
| D10 | Экспорт скрипта называется `handle` для любого хука. | Имена хуков содержат точки, а Rust-макрос экспортирует идентификатор функции. Модуль и так привязан к одному хуку. |
| D11 | Снимок конфигурации передаётся целиком (state of the world), а не дельтами: long-poll возвращает полный снимок, если версия новее. | Ни одной ошибки применения дельт. Прецедент: xDS в Envoy начинался с полных снимков, delta-xDS добавили позже ради масштаба. Дельты в roadmap, если снимок вырастет. |
| D12 | Логи вызовов и состояние circuit breaker для консолей в PoC отдаются polling-ом, в MVP через SSE от control plane с `Last-Event-ID` по порядковому номеру вызова. Аутентификация стрима по сессионной cookie. | Поток однонаправленный, SSE даёт переподключение с продолжением бесплатно. |
| D13 | Витрина демо-магазина это route group `(storefront)` в Next.js. Бэкенд магазина на FastAPI отдаёт ей API и является оператором для платформы. | Решение фронтенда из brief-1. |
| D14 | Статусы модуля: `uploaded`, `validating`, `validated`, `rejected`, `archived`. «Активен» это свойство привязки «тенант, хук», а не модуля. | Один модуль может быть валиден, но не активен, и наоборот: при откате активным становится старый. |
| D15 | Второй язык скриптов выбирается после спайка. Python исключён: Python PDK не обновлялся с июня 2025. | Проверено 24.09. |

## 5. Архитектура data plane в M0

### 5.1 Пакеты

```
internal/
  sandbox/            интерфейсы рантайма, типизированные ошибки, ModuleSpec, проверка импортов
  sandbox/extismrt/   реализация на Extism
  sandbox/sandboxtest/ общий набор тестов, который обязана пройти любая реализация
  pool/               пул инстансов на ключ и менеджер пулов с глобальным лимитом
  modstore/           получение байтов модуля по хешу (M0: файловая система), проверка хеша
  schema/             компиляция и проверка JSON Schema
  config/             модель снимка, Source (M0: FileSource), Store с атомарной заменой
  execproto/          контракт gateway ↔ executor: ExecuteRequest, ExecuteResult, Outcome, интерфейс Executor
  executor/           реализация execproto.Executor: кеш компиляции, пулы, вызов, проверка выхода
  gateway/            допуск и маршрутизация: ключ, хук, схема входа, привязка, вызов execproto.Executor
  gateway/httpapi/    HTTP-обработчики публичного API, маппинг исходов в статусы
  observe/            запись о вызове, интерфейс Sink (M0: slog)
cmd/dataplane/        сборка зависимостей, HTTP-сервер, graceful shutdown
cmd/demo/             демо
```

### 5.2 Правила зависимостей

- `gateway` зависит от `execproto`, `config`, `schema`, `observe`. **Никогда** от `executor`, `pool`, `sandbox`, `modstore`.
- `executor` зависит от `execproto`, `config`, `sandbox`, `pool`, `modstore`, `schema`, `observe`. **Никогда** от `gateway`.
- `sandbox` не зависит ни от чего внутреннего. `sandbox/extismrt` зависит только от `sandbox`.
- `execproto` не зависит ни от чего внутреннего и содержит только типы и интерфейс. Типы повторяют будущий protobuf один к одному: только примитивы, срезы и map, без указателей на внутренние структуры, без `context`-значений, без функций.
- Связывает `gateway` и `executor` только `cmd/dataplane`: `gateway.New(..., exec execproto.Executor)` получает `executor.New(...)`.

Поэтому разделение на два процесса в MVP сводится к трём шагам: `execproto/grpc` с клиентом и сервером, два main-пакета вместо одного, executor получает свой `config.Source`. Код gateway и executor не меняется.

### 5.3 Архитектурный тест

`internal/archtest` содержит тест, который через `go list -deps -json` проверяет правила из 5.2 и падает при нарушении. Это fitness function: граница проверяется в CI, а не держится на дисциплине. Аналоги в индустрии: ArchUnit в Java, depguard в golangci-lint.

### 5.4 Снимок конфигурации в двух местах

После разделения у gateway и executor-а будут свои копии снимка. Gateway передаёт в `ExecuteRequest` версию определения хука, хеш модуля и версию конфига тенанта. Если у executor-а снимок старее запрошенного, он возвращает `unavailable` с причиной `stale_config`, и gateway повторяет вызов (MVP). В M0 снимок один, но executor уже ищет определение хука по `(hook, def_version)`, а не «текущее по имени». Это делает правило соблюдаемым с первого дня.

## 6. Контракты

### 6.1 Публичный Invoke

#### 6.1.1 Запрос

```
POST /v1/hooks/{hook}/invoke
Authorization: Bearer <api_key>
Content-Type: application/json

{
  "tenant_id": "merchant-a",            // external_id, обязателен
  "payload": { ... },                    // JSON по input_schema хука, обязателен
  "deadline_ms": 200,                    // опционально, бюджет вызывающей стороны
  "idempotency_key": "order-123:checkout.discount"   // опционально
}
```

- Размер тела не больше 1 МиБ, иначе 413.
- `deadline_ms` по умолчанию `hook.timeout_ms + 100`, не больше 30000. Значения по умолчанию пересматриваются после спайка.

#### 6.1.2 Ответ

```
HTTP/1.1 200 OK
X-Hook-Outcome: ok

{
  "outcome": "ok",
  "result": { ... },                     // только при ok: JSON по output_schema хука
  "effects": [ {"type": "...", "key": "...", "payload": {...}} ],  // только при ok, может быть пустым
  "error": null,                         // строка при handler_error, unavailable
  "duration_ms": 3,                      // время от получения запроса до ответа
  "module_hash": "sha256:..."            // при исполнении скрипта
}
```

Ошибки запроса отдаются в формате RFC 9457 (problem details): `{"type", "title", "status", "detail"}`, `Content-Type: application/problem+json`.

#### 6.1.3 Исходы и статусы

| Ситуация | HTTP | outcome | Запускался ли скрипт | Есть ли смысл повторять |
|---|---|---|---|---|
| Скрипт отработал | 200 | `ok` | да | — |
| Хук существует, у тенанта нет скрипта или тенант не зарегистрирован | 200 | `no_handler` | нет | нет |
| Скрипт не уложился в лимит времени | 200 | `timeout` | да | почти никогда |
| Скрипт упал, трап, превышение памяти, выход не по схеме, неразрешённый эффект | 200 | `handler_error` | да | нет |
| Превышена квота тенанта (MVP) | 429 | `quota_exceeded` | нет | да, после `Retry-After` |
| Платформа не смогла обслужить: пул насыщен, дедлайн истёк до запуска скрипта, модуль недоступен, внутренняя ошибка | 503 | `unavailable` | нет | да |
| Нет или неверный ключ | 401 | — | | |
| Неизвестный хук | 404 | — | | |
| Тело не JSON, нет обязательных полей, payload не проходит `input_schema` | 400 | — | | |
| Тело больше лимита | 413 | — | | |

Почему `timeout` и `handler_error` возвращаются с кодом 200. HTTP-статус описывает отношения между оператором и платформой. Платформа выполнила свою работу: исполнила сторонний код в лимитах и сообщила результат. Сбой находится в коде тенанта и является данными о вызове. Семантические 502/504 рассматривались и отвергнуты: инфраструктура оператора трактует 5xx как отказ сервера. Retry-middleware стал бы повторять зависший скрипт, алерты по доле 5xx срабатывали бы от бага одного тенанта, outlier detection в Envoy или Istio выкидывал бы здоровые реплики gateway. Кроме того, оператор перестал бы отличать собственный таймаут балансировщика от таймаута скрипта. Прецедент: AWS Lambda `Invoke` при ошибке функции возвращает 200 с заголовком `X-Amz-Function-Error`.

Граница между `timeout` и `unavailable` проходит по моменту запуска скрипта. Если дедлайн истёк во время ожидания пула или создания инстанса, скрипт не запускался, это `unavailable`. `timeout` бывает только у запущенного скрипта.

#### 6.1.4 Служебные эндпоинты

- `GET /healthz`: процесс жив.
- `GET /readyz`: снимок конфигурации загружен, иначе 503.

### 6.2 Снимок конфигурации (control plane → data plane)

```
GET /internal/v1/config/snapshot?after_version=<n>&wait_s=<s>
Authorization: Bearer <internal_token>

200 OK        полный снимок, если его версия > after_version
304 Not Modified   по истечении wait_s без изменений
```

Без `after_version` сразу отдаётся текущий снимок. `wait_s` по умолчанию 30, не больше 60. Сервер отвечает немедленно, как только версия становится больше `after_version`.

```json
{
  "version": 42,
  "api_keys": [
    {"id": "key_01", "name": "shop-prod", "sha256": "<hex от ключа>"}
  ],
  "hooks": [
    {
      "name": "checkout.discount",
      "def_version": 3,
      "input_schema":  { "$schema": "https://json-schema.org/draft/2020-12/schema", "...": "..." },
      "output_schema": { "...": "схема поля result" },
      "timeout_ms": 50,
      "memory_max_pages": 256,
      "allowed_host_functions": [],
      "allowed_effect_types": [],
      "sample_input": { "...": "..." }
    }
  ],
  "tenants": [
    {"external_id": "merchant-a", "concurrency_limit": 4, "rate_limit_rps": 100}
  ],
  "bindings": [
    {
      "tenant_id": "merchant-a",
      "hook": "checkout.discount",
      "module_hash": "sha256:<hex>",
      "config": {"threshold": "1000", "percent": "10"},
      "config_version": 7
    }
  ]
}
```

- В снимке всегда только текущее определение каждого хука. Старые версии определений executor держит в памяти, пока на них ссылаются закешированные модули.
- `config` это map строк: так устроен конфиг Extism. Типизация значений остаётся на стороне скрипта.
- `rate_limit_rps` в M0 игнорируется, поле есть в контракте ради совместимости.
- В M0 `FileSource` читает документ ровно этого формата из файла. HTTP-источник с long-poll добавляется вместе с control plane без изменений в потребителях.

Модули хранятся по адресу, вычисляемому из хеша: в M0 это `<modules_dir>/<hex>.wasm`, позже `s3://<bucket>/modules/sha256/<hex>`. Data plane проверяет хеш после загрузки.

### 6.3 Валидация модуля (control plane → executor)

```
POST /internal/v1/modules/validate
Content-Type: application/json
{ "module_hash": "sha256:<hex>", "hook": { ...определение хука, как в снимке... } }

200 OK
{
  "ok": false,
  "checks": [
    {"name": "fetch",    "ok": true},
    {"name": "compile",  "ok": true},
    {"name": "exports",  "ok": true},
    {"name": "imports",  "ok": false, "detail": "import extism:host/env.http_request is not allowed for this hook"},
    {"name": "sample_call", "ok": false, "detail": "skipped"}
  ]
}
```

Контракт фиксируется в M0, реализация в stretch. Проверки `exports` и `imports` executor выполняет при любой компиляции модуля, независимо от эндпоинта, как защиту на случай, если control plane валидацию пропустил.

### 6.4 ABI скрипта

- Экспорт `handle`, без аргументов в смысле wasm. Вход и выход передаются через Extism.
- Вход: JSON-объект `payload` из запроса, байты как есть.
- Выход: JSON-объект `{"result": {...}, "effects": [...]}`. Отсутствующий `effects` равен пустому списку.
- Конфиг: `config::get("<key>")` в PDK.
- Логи: `info!`, `warn!` и т. п. в PDK. На вызов не больше 16 КиБ и 100 строк, лишнее отбрасывается со строкой-маркером `[truncated]`.
- Ошибка: скрипт возвращает ошибку средствами PDK, текст попадает в `error` ответа с исходом `handler_error`, обрезанный до 1 КиБ.
- Выход больше 1 МиБ: `handler_error`.
- `key` эффекта по умолчанию равен `idempotency_key + ":" + <индекс>`, если скрипт его не задал. Без ключа идемпотентности поле остаётся пустым.

### 6.5 Запись о вызове

Формат, который executor отдаёт в `observe.Sink`. В M0 это строка slog, в MVP строка таблицы `invocations`:

```
ts, tenant_id, hook, hook_def_version, module_hash, config_version, outcome, error,
duration_ms, exec_ms, cold_start (bool), idempotency_key, logs[], executor_id
```

## 7. Абстракция рантайма

### 7.1 Интерфейсы

```go
package sandbox

type Runtime interface {
    Compile(ctx context.Context, wasm []byte, spec ModuleSpec) (Module, error)
    Close(ctx context.Context) error
}

type ModuleSpec struct {
    MemoryMaxPages       uint32
    Timeout              time.Duration   // лимит исполнения одного вызова
    AllowedHostFunctions []string        // пространство extism:host/user
}

type Module interface {
    Instantiate(ctx context.Context, cfg map[string]string) (Instance, error)
    Close(ctx context.Context) error
}

type Instance interface {
    // Call исполняет export. Возвращает типизированную ошибку.
    // После любой ошибки инстанс считается непригодным.
    Call(ctx context.Context, export string, input []byte) (CallResult, error)
    Close(ctx context.Context) error
}

type CallResult struct {
    Output []byte
    Logs   []LogLine
}

var (
    ErrTimeout     = errors.New("sandbox: execution deadline exceeded")
    ErrTrap        = errors.New("sandbox: wasm trap")
    ErrGuest       = errors.New("sandbox: guest returned error")
    ErrClosed      = errors.New("sandbox: instance closed")
    ErrInvalidModule = errors.New("sandbox: module violates spec")
)
```

Ошибки оборачиваются с деталями (`fmt.Errorf("%w: %s", ErrTrap, msg)`), потребители проверяют через `errors.Is`. `ErrInvalidModule` возвращает `Compile`, если импорты или экспорты не соответствуют спецификации. Превышение памяти в Rust проявляется как трап (`unreachable` после неудачного `memory.grow`), поэтому отдельной ошибки OOM нет. Если спайк покажет, что её можно надёжно отличить, она добавится.

### 7.2 Проверка импортов и экспортов

Выполняется в `Compile` до передачи модуля рантайму. Логика общая, в пакете `sandbox`, разбор секций через `wazero` (компиляция без инстанцирования даёт список импортов и экспортов). Это осознанная связь абстракции с wazero: wazero здесь служит парсером формата wasm, а не рантаймом, не требует cgo и не зависит от Extism. Фиксируется в ADR 0003.

- Экспорт `handle` обязателен.
- Импорты из `extism:host/env` разрешены по allowlist ядра: работа с памятью, вводом-выводом, ошибками, `config_get`, `var_get`, `var_set`, `log_*`, `get_log_level`. `http_request`, `http_status_code`, `http_headers` запрещены. Если спайк покажет, что Rust PDK импортирует их всегда, даже без использования, запрет переносится на рантайм: Go SDK отклоняет любой HTTP-запрос при пустом `AllowedHosts`.
- Импорты из `extism:host/user` должны входить в `AllowedHostFunctions`. В M0 список пуст.
- Любое другое пространство имён, включая `wasi_snapshot_preview1`, запрещено. WASI в M0 выключен.

### 7.3 Реализация на Extism: особенности

Проверено по исходникам go-sdk v1.7.1 24.09.

- Каждый `CompiledPlugin` создаёт свой wazero-рантайм. Лимит памяти задаётся на рантайм, поэтому модуль компилируется на пару «хеш, определение хука». Все рантаймы используют один общий `wazero.CompilationCache`, чтобы ядро Extism не компилировалось заново для каждого модуля. Эффект измеряется в спайке. Время жизни скомпилированных модулей привязано к кешу, поэтому кеш закрывается только в `Runtime.Close` после закрытия всех модулей.
- `manifest.Timeout > 0` обязателен: только тогда SDK включает `WithCloseOnContextDone`. Без этого бесконечный цикл не прерывается.
- `CompiledPlugin.Instance` отдаёт каждому инстансу **ссылку на общий map** `manifest.Config`. Конфиг тенанта задаётся **присваиванием нового map** `inst.Config = copy(cfg)`. Изменение map на месте утекло бы во все инстансы модуля, включая инстансы других тенантов. На это есть отдельный тест.
- `var_get` и `var_set` разрешены (7.2), поэтому в манифесте всегда задаётся `max_var_bytes` (64 КиБ в M0). Иначе скрипт может неограниченно копить переменные в инстансе в обход лимита линейной памяти.
- Уровень логирования глобальный на процесс (`extism.SetLogLevel`), обработчик свой у каждого инстанса (`SetLogger`). Уровень по умолчанию может отфильтровать логи гостя, поэтому `Runtime` при создании явно выставляет уровень, а спайк проверяет, что строки `info` доходят до обработчика. Обёртка устанавливает обработчик, который пишет в буфер текущего вызова с лимитом из 6.4. Инстанс используется одним вызовом за раз, поэтому буфер переключается без гонок.
- После таймаута wazero закрывает модуль, следующий `Call` возвращает `module is closed`. Таймаут распознаётся по `sys.ExitError` с кодом `ExitCodeDeadlineExceeded` или `ExitCodeContextCanceled`, а также по `ctx.Err()`.
- Гостевая куча сохраняется между вызовами, Extism сбрасывает только свою память. Поэтому инстансы никогда не разделяются между тенантами (раздел 8).
- Совместимость с wazero 1.12 проверяется в спайке через `replace`. Если не заведётся, остаёмся на 1.9.

## 8. Пул инстансов

### 8.1 Ключ

`(tenant_id, hook, hook_def_version, module_hash, config_version)`. Скомпилированный модуль при этом общий для всех тенантов с одинаковым `(module_hash, hook_def_version)`.

При смене конфига, версии скрипта или определения хука меняется ключ. Старый пул никто не инвалидирует явно, он освобождается по простою. Явной инвалидации нет, значит, нет и гонок инвалидации с вызовами в полёте.

### 8.2 Поведение

```go
type Pool interface {
    Acquire(ctx context.Context) (*Lease, error)   // ErrSaturated, ошибка создания инстанса
}
func (l *Lease) Instance() sandbox.Instance
func (l *Lease) Release(healthy bool)
```

- `Acquire` отдаёт свободный инстанс, если он есть. Иначе создаёт новый, если не достигнут лимит ключа и глобальный лимит. Иначе ждёт освобождения до `min(дедлайн ctx, acquire_timeout)` и возвращает `ErrSaturated`.
- Инстанс создаётся вне блокировок менеджера. Время создания считается в дедлайн вызова, это холодный старт.
- `Release(false)` закрывает инстанс: после таймаута, трапа, ошибки гостя, закрытого модуля. `Release(true)` возвращает инстанс в пул, если число его вызовов меньше `max_uses`, иначе закрывает.
- Фоновый процесс раз в `reap_interval` закрывает инстансы, простаивающие дольше `idle_ttl`, и удаляет пустые пулы.
- `Lease` защищён от двойного `Release`.
- Глобальный лимит инстансов на процесс это семафор. Он защищает процесс executor-а от OOM: в худшем случае память равна `global_max × memory_max_pages × 64 КиБ` плюс накладные расходы на инстанс, которые измеряет спайк.

### 8.3 Параметры M0

| Параметр | Значение M0 | Источник |
|---|---|---|
| Лимит на ключ | `tenant.concurrency_limit` (по умолчанию 4) | снимок |
| `global_max` | 256 | флаг, пересмотр после спайка |
| `acquire_timeout` | 10 мс | флаг |
| `max_uses` | 1000 | флаг |
| `idle_ttl` | 60 с | флаг |
| `reap_interval` | 10 с | флаг |

## 9. Executor

### 9.1 Алгоритм Execute

1. Найти определение хука по `(hook, def_version)` и привязку. Нет: `unavailable` с причиной `stale_config` (в M0 недостижимо, но код есть).
2. Взять скомпилированный модуль из кеша по `(module_hash, def_version)`. Промах: загрузить байты из `modstore`, проверить хеш, `Compile`. Конкурентные промахи на один ключ компилируют модуль один раз (singleflight). Ошибка загрузки: `unavailable`. `ErrInvalidModule`: `handler_error` с деталями.
3. `Acquire` из пула. `ErrSaturated`, ошибка создания инстанса или истёкший дедлайн: `unavailable`.
4. `Call("handle", payload)` с контекстом, дедлайн которого равен `min(оставшийся дедлайн запроса, hook.timeout_ms)`.
5. Разобрать выход, проверить `result` по `output_schema`, проверить типы эффектов, проставить ключи эффектов.
6. `Release(healthy)`: `healthy` только если `Call` завершился без ошибки. Невалидный выход при успешном `Call` не портит инстанс.
7. Отправить запись о вызове в `observe.Sink` и вернуть результат.

Кеш скомпилированных модулей в M0 не ограничен по размеру: модулей единицы. LRU с лимитом добавляется в MVP по числам из спайка. Конкурентная компиляция защищена singleflight уже сейчас.

### 9.2 Маппинг в исходы

| Условие | outcome | Инстанс |
|---|---|---|
| `Call` успешен, выход валиден | `ok` | в пул |
| `errors.Is(err, ErrTimeout)` | `timeout` | закрыть |
| `ErrTrap`, `ErrGuest`, `ErrClosed` во время вызова | `handler_error` | закрыть |
| Выход не JSON, не проходит `output_schema`, больше 1 МиБ, неразрешённый эффект | `handler_error` | в пул |
| `ErrInvalidModule` при компиляции | `handler_error` | — |
| `ErrSaturated`, ошибка `Instantiate`, дедлайн истёк до `Call` | `unavailable` | — |
| Ошибка `modstore` (нет файла, хеш не совпал) | `unavailable` | — |

## 10. Gateway

1. Аутентификация: SHA-256 от Bearer-токена сравнивается с хешами из снимка за постоянное время. Ошибка: 401.
2. Хук по имени из текущего снимка. Нет: 404.
3. Разбор тела, лимит размера, обязательные поля: 400 или 413.
4. Проверка `payload` по `input_schema`. Схемы компилируются один раз при смене снимка. Ошибка: 400 с указанием, какое поле не прошло.
5. Привязка по `(tenant_id, hook)`. Нет: `no_handler`, executor не вызывается.
6. Дедлайн запроса: `deadline_ms` или значение по умолчанию.
7. `execproto.Executor.Execute(ctx, req)`. Ретраев в M0 нет: процесс один.
8. `httpapi` переводит результат в статус, тело и `X-Hook-Outcome` по таблице 6.1.3.

## 11. Скрипты-фикстуры

Cargo workspace в `examples/scripts/rust/`, `extism-pdk` последней версии, таргет `wasm32-unknown-unknown`, профиль release с `opt-level = "s"` и `lto = true`.

| Крейт | Поведение | Назначение |
|---|---|---|
| `discount` | Скидка `percent` из конфига, если `customer.lifetime_spend >= threshold`, иначе 0. Пишет строку в лог. | Демо, бенчмарк тёплого вызова |
| `infinite-loop` | Бесконечный цикл, который компилятор не может выбросить. | Таймаут |
| `memory-bomb` | Растит вектор до отказа аллокатора. | Лимит памяти |
| `counter` | Статический счётчик, возвращает его значение после инкремента. | Изоляция тенантов, сохранение кучи, `max_uses` |
| `guest-error` | Возвращает ошибку через PDK. | `ErrGuest` |
| `echo-config` | Возвращает весь запрошенный конфиг. | Изоляция конфига между тенантами |
| `bad-output` | Возвращает выход, не соответствующий схеме. | Проверка выхода |
| `http-call` | Пытается сделать HTTP-запрос. | Проверка импортов или запрета в рантайме |

Собранные `.wasm` коммитятся в `dataplane/testdata/wasm/`, чтобы `go test` не требовал Rust. Пересборка: `go run ./tools/buildscripts` из `dataplane/`. Программа на Go, чтобы одинаково работала на Windows и Linux. CI в отдельной задаче проверяет, что крейты собираются. Побайтовое сравнение с закоммиченными файлами не делается: сборки Rust не гарантируют воспроизводимость между машинами.

## 13. Тестирование

- **Контрактный набор `sandboxtest`.** Функция `Run(t, factory)`, которую обязана пройти любая реализация `sandbox.Runtime`: исходы из 9.2, изоляция, лимиты. Вызывается из `extismrt`. Если рантайм придётся менять, новая реализация проверяется тем же набором.
- **Unit:** пул (лимиты, ожидание, `max_uses`, простой, двойной `Release`, глобальный семафор, гонки под `-race`), `config` (разбор, атомарная замена), `schema`, маппинг исходов в `httpapi`, проверка импортов на синтетических модулях.
- **Интеграционные с настоящими скриптами:** каждая строка 9.2, таймаут не мешает параллельному вызову другого тенанта, два тенанта с одинаковым модулем `counter` видят независимые счётчики, два тенанта с одинаковым модулем `echo-config` видят каждый свой конфиг, после `max_uses` инстанс пересоздаётся (счётчик `counter` сбрасывается).
- **HTTP end-to-end:** `httptest.Server` с полным `cmd/dataplane`, сценарий демо.
- **Архитектурный тест** из 5.3.
- **CI** (`ubuntu-latest`): `gofmt -l`, `go vet`, `go test -race ./...`, короткий прогон бенчмарков, сборка Rust-скриптов.

## 14. Демо

`cmd/demo` собирает `cmd/dataplane` во временную директорию, запускает с `examples/demo/snapshot.json` и `testdata/wasm`, ждёт `/readyz`, прогоняет сценарий из раздела 2 по HTTP, печатает таблицу (шаг, тенант, ожидаемый исход, фактический исход, HTTP, латентность, PASS/FAIL) и корректно останавливает процесс. С флагом `--target <url>` работает против уже запущенного data plane. Код возврата ненулевой, если хоть один шаг FAIL, поэтому демо заодно служит smoke-тестом.

Шаг «A параллельно с B»: 20 вызовов `merchant-a` запускаются в тот момент, когда `merchant-b` висит в цикле. Латентность `merchant-a` p50 и max сравнивается с прогоном без `merchant-b`.

## 16. Риски

| Риск | Признак | Действие |
|---|---|---|
| Go SDK Extism несовместим с wazero 1.12 или Go 1.26 | S10 падает | Остаёмся на wazero 1.9, в ADR фиксируется план форка или ухода на свой ABI |
| Инстанцирование дорогое (единицы мс и выше) | S2 | Тёплый пул обязателен, прогрев переносится ближе к M1 |
| Таймаут неточный (прерывание запаздывает) | S7 | Дедлайн контекста с запасом, в спек записывается фактическая точность |
| OOM выглядит как трап без различимых признаков | S8 | Оставляем `handler_error` с текстом трапа, отдельный код не вводим |
| Rust PDK всегда импортирует HTTP-функции | S11 | Запрет переносится на рантайм, в проверке импортов HTTP допускается |
| CRLF ломает CI на Linux | красный CI | `.gitattributes` с первого коммита |
