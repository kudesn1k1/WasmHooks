# M3 · потеря executor-а под нагрузкой

Из корня репозитория запустите команду на машине с Docker Engine в режиме Linux-контейнеров, kind 0.31, kubectl, Git и Python 3.10+.

~~~sh
python -B deploy/kind/run.py --output docs/reviews/m3-kind-report.json
~~~

Команда создаёт или повторно использует выделенный кластер `wasmhooks-m3`. По умолчанию выбран одноузловой kind с Kubernetes 1.34.3. Три процесса executor работают в отдельных pod-ах. Для начального запуска нужен доступ к реестрам образов. Скрипт собирает три приложения, загружает образы в kind, разворачивает PostgreSQL, MinIO, control plane, gateway, executor-ы и магазин. PVC сохраняют данные между запусками. Init-контейнеры применяют миграции и создают бакет. Ключ установки выпускается через `controlplane apikey create` и сохраняется в Kubernetes Secret. Локальные порты выделяются автоматически на 127.0.0.1. Команда использует временный kubeconfig.

Для повторного эксперимента с теми же локальными образами доступны `--skip-build` и `--skip-load`. После изменения приложения для нового прогона нужны пересборка и загрузка образа. Сценарий выставляет скидки 10% и 25% для merchant-a и merchant-b, создаёт привязки дополнительных тенантов через API и удаляет один pod executor-а. После серии на двух узлах он восстанавливает исходное состояние планирования, в том числе при ошибке. Кластер остаётся доступен для изучения.

| Параметр | По умолчанию | Что задаёт |
| --- | --- | --- |
| `--rps` | 15 | Суммарная фоновая нагрузка. Чекауты двух магазинов чередуются с прямыми Invoke дополнительных тенантов |
| `--extra-pairs` | 12 | Дополнительные тенанты, включая отдельную пару для проверки предзагрузки |
| `--phase-seconds` | 5 | Дополнительное время фоновой нагрузки в каждой стабильной фазе |
| `--series-rounds` | 3 | Число последовательных вызовов каждой пары в стабильной фазе и покупок в каждом магазине |
| `--convergence-seconds` | 30 | Предельное время удаления из кольца и допуска замены |

Код выхода 0 означает PASS. Отчёт сохраняет параметры, время, Git-ревизию, хеш исходников, ID образов и pod-ов, владельцев пар, измерения чекаута и Invoke, p99, исходы, долю fallback среди покупок, попытки по executor-ам и успешные повторы. В разделе `phases` видны два переходных окна и три стабильных интервала. Скидка вычисляется для лояльного покупателя, результат сверяется с ценой товара в копейках. Отдельные вызовы проверочной серии связываются по ключам идемпотентности с записями executor-а. Пара предзагрузки получает уникальный хеш модуля. При потере её владельца сценарий читает событие `module preloaded` в логе нового владельца до первой отправки Invoke этой пары.

После входа замены сценарий повторяет проверочную серию для всех исходных пар. Если новый pod не получил ни одной из них, сценарий подбирает для него дополнительную пару, регистрирует привязку и сверяет успешный Invoke с журналами executor-ов по ключу идемпотентности. Отчёт хранит этот вызов в `recovered.replacement_probe`. Список `moved_pairs` учитывает только исходные пары.

Проверки логики отчёта и подготовки среды можно выполнить без Docker.

~~~sh
python -B -m unittest discover -s deploy/kind
~~~
